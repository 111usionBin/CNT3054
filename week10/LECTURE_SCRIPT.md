## 1. 토픽모델링 Ⅱ
토픽 해석과 변화 분석 실습

오늘은 여러분이 조별로 모아 둔 댓글이나 리뷰를 가지고 실습하겠습니다. 제가 준비한 특정 데이터의 결과를 똑같이 따라갈 필요는 없습니다. 각 조의 파일을 코드에 넣고, 어떤 토픽이 나오는지 직접 보시면 됩니다. 그중 관심이 가는 토픽을 골라서 원문을 읽어보겠습니다. 단어 목록만 봤을 때 생각한 내용과 실제 글쓴이가 하는 이야기가 같은지 확인해 주세요. 제가 먼저 파일을 넣는 위치와 실행 방법을 보여드리겠습니다. 날짜가 들어 있는 자료를 가진 조는 뒤에서 월별 변화도 살펴볼 수 있습니다. 이번 실습은 수업 중에 여러분의 데이터로 실행해 보는 활동이고, 별도로 제출할 과제는 없습니다.

## 2. 우리 조 데이터에서 관심 있는 토픽 하나를 읽어봅니다

오늘 여러분이 하실 일부터 말씀드리겠습니다. 지금까지 수집한 댓글이나 리뷰 CSV를 하나 골라 주세요. 그 파일을 분석하면 코드가 토픽별 단어와 원문 파일을 함께 만들어 줍니다. 여러분은 단어 목록에서 관심 있는 토픽을 하나 고르고, 그 토픽에 속한 글을 읽으시면 됩니다. 예를 들어 T1을 골랐다면 T1_read.md를 여시면 됩니다. 조원들과 화면을 같이 보면서 이 글들이 공통으로 무엇을 이야기하는지 말해 보세요. 처음 생각한 이름이 원문과 맞지 않으면 바꾸셔도 됩니다. 제가 중요하게 보는 부분은 원문을 읽은 뒤 여러분이 왜 그 이름을 붙였는지 서로 납득할 수 있는가입니다. 우선 같은 코드를 받을 수 있도록 저장소부터 열겠습니다.

## 3. GitHub Desktop에서 최신 코드 받기

GitHub Desktop에서 CNT3054 저장소를 선택해 주세요. 위쪽 브랜치가 main인지 확인한 뒤 Fetch origin을 누르시면 됩니다. 새 변경 사항이 있으면 Pull origin이 나타나니 이어서 눌러 주세요. 이번에 사용할 파일은 week10 폴더의 team_lab.py와 team_config.json입니다. 이전 자료에 있던 run_lab.py 대신 이 파일을 사용하겠습니다. 내려받기가 끝나면 Open in Visual Studio Code를 눌러 주세요. 저장소가 처음인 분은 File 메뉴의 Clone repository에서 화면 아래 주소를 넣으시면 됩니다. 편집기가 열리면 왼쪽에서 week10 폴더를 찾아보겠습니다.

## 4. 조별 CSV를 넣을 위치

왼쪽 탐색기에서 week10 폴더를 펼쳐 주세요. 그 안의 data 폴더에 여러분이 수집한 CSV를 복사하겠습니다. 파일 이름은 my_comments.csv로 맞춰 주세요. 원본 파일은 따로 보관하고 복사한 파일로 진행하시면 됩니다. 한 행에 댓글 또는 리뷰 한 개가 들어 있는 자료를 골라 주세요. 엑셀 파일만 있다면 다른 이름으로 저장에서 CSV UTF-8 형식을 선택하시면 됩니다. CSV 안의 열 이름을 지금 모두 바꿀 필요는 없습니다. 어떤 열에 본문이 들어 있는지는 다음 단계에서 코드에 알려주겠습니다. 파일을 넣었으면 위쪽 Terminal 메뉴에서 New Terminal을 눌러 주세요.

## 5. 실행 환경 준비

이제 터미널에 첫 번째 명령을 입력해 주세요. 기존 수업에서 쓰던 .venv에 이번 코드가 사용하는 패키지를 설치하는 명령입니다. 이미 설치된 패키지는 그대로 사용합니다. .venv가 없는 컴퓨터에서 처음 시작한다면 아래에 적힌 uv venv 명령을 먼저 실행해 주세요. 설치가 끝나면 두 번째 명령으로 코드의 실행 항목이 보이는지 확인하겠습니다. 화면에 inspect, run, time이 나오면 파일과 실행 환경을 찾은 상태입니다. 앞으로 입력할 명령도 모두 이 터미널에서 실행하시면 됩니다. 오류가 나면 다음 단계로 계속 넘어가기 전에 어느 파일이나 패키지를 찾지 못했는지 메시지를 함께 보겠습니다.

## 6. 실행 명령은 inspect, run, time입니다

지금 화면은 실제 코드에서 help 명령을 실행한 결과입니다. inspect는 CSV에 어떤 열이 있는지 보여줍니다. run은 토픽을 학습하고 읽어볼 원문 파일을 만듭니다. time은 날짜를 사용해 분석한 결과가 있을 때 월별 비중을 계산합니다. 여러분은 이 세 단어를 한 번에 입력하는 것이 아니라 필요한 단계에서 하나씩 입력하시면 됩니다. 먼저 inspect를 사용하겠습니다. 이 단계에서는 댓글 내용이나 토픽 결과가 나오지 않고 파일의 행 수와 열 이름만 나옵니다. 자신의 자료에서 본문이 어느 열인지 정확히 찾기 위한 과정입니다.

## 7. CSV의 본문 열 이름 확인

화면의 명령을 입력해 주세요. 여러분의 CSV 파일을 찾으면 코드가 행 수와 열 이름을 출력합니다. 그중 실제 댓글 문장이나 리뷰 본문이 들어 있는 열을 찾아 주세요. 열 이름이 text인 조도 있고 comment_text나 content인 조도 있을 수 있습니다. 작성자 아이디나 제목만 들어 있는 열을 선택하면 우리가 읽으려는 내용과 다른 것을 분석하게 됩니다. 열 이름만 보고 판단하기 어렵다면 CSV를 열어서 그 열의 내용을 확인해 주세요. 찾은 열 이름을 다음 화면의 text_column 값에 그대로 넣겠습니다. 파일을 찾지 못했다면 week10/data 안에 my_comments.csv가 있는지 먼저 확인해 주세요.

## 8. team_config.json에서 본문 열 연결

왼쪽에서 team_config.json을 열어 주세요. 화면의 text_column 값은 처음에 text로 되어 있습니다. 앞에서 찾은 본문 열 이름이 comment_text라면 text 대신 comment_text를 적으시면 됩니다. 따옴표와 쉼표는 그대로 두고 값만 바꿔 주세요. 날짜를 사용하지 않을 조는 date_column을 null로 두면 됩니다. input과 out은 각각 입력 파일과 결과 폴더 위치이므로 지금은 그대로 사용하겠습니다. topics도 처음에는 4로 두겠습니다. 제가 네 개를 정답으로 지정한 것은 아니고, 우선 결과를 읽어보기 위한 시작값입니다. 수정한 뒤 Ctrl+S로 저장해 주세요.

## 9. 자료에 맞춰 바꿀 설정

설정값을 바꾸는 방법을 조금 더 구체적으로 보여드리겠습니다. CSV의 본문 열이 text라면 지금 상태를 유지하시면 됩니다. 본문 열이 comment_text라면 해당 문자열로 바꿔 주세요. 날짜는 댓글이나 리뷰를 실제로 작성한 시각을 사용해야 합니다. 모든 댓글을 오늘 수집했다는 이유로 오늘 날짜를 넣으면 과거의 변화가 사라집니다. 작성일 열이 없다면 null로 두고 원문 해석까지 진행하시면 됩니다. 파일을 읽을 때 글자가 깨지면 CSV UTF-8로 다시 저장하는 방법이 가장 간단합니다. 설정이 끝났으면 이제 여러분의 자료로 분석을 실행하겠습니다.

## 10. 우리 조 데이터로 토픽모델링 실행

저장하셨으면 화면의 run 명령을 입력해 주세요. 코드가 여러분이 지정한 본문 열을 읽고, 각 문장에서 명사와 영문 토큰을 추출합니다. 그 빈도를 바탕으로 토픽모델을 학습합니다. 터미널에 T1, T2처럼 토픽별 주요 단어가 나오면 분석 결과가 생성된 것입니다. 조마다 수집한 주제와 문서 수가 다르기 때문에 나오는 단어도 서로 다를 겁니다. 특정 토픽이 꼭 나와야 하는 기준 답안은 없습니다. 출력 아래에는 실제 분석한 문서 수와 제외한 문서 수도 나옵니다. 빈 글이나 분석에 사용할 어휘가 남지 않은 글이 얼마나 있었는지 함께 봐 주세요. 결과를 보기 전에 코드가 무엇을 묶었는지 짧게 설명해드리겠습니다.

## 11. 한 문서에는 여러 토픽이 섞일 수 있습니다

이 부분은 제가 코드가 계산하는 값을 설명해드리겠습니다. fit_transform에서 나오는 theta에는 문서마다 각 토픽의 비중이 들어 있습니다. 한 댓글에 가격 이야기와 작품 이야기가 함께 있으면 두 토픽의 비중이 모두 나타날 수 있습니다. 코드 아래쪽에서는 비중이 가장 큰 토픽을 dominant_topic으로 따로 저장합니다. 이 열은 문서를 찾아보기 쉽게 만든 대표 표시입니다. 그 문서가 오직 한 가지 이야기만 한다고 단정할 필요는 없습니다. 여러분이 잠시 뒤 원문을 읽을 때는 이 점을 기억해 주세요. 단어가 비슷하더라도 글쓴이가 말하는 경험이나 입장은 다를 수 있습니다. 이제 생성된 파일을 열어보겠습니다.

## 12. 결과 폴더에서 열 파일

왼쪽 탐색기에서 team_outputs를 펼쳐 주세요. 먼저 topics.md를 열면 토픽별 상위 단어를 볼 수 있습니다. T1_read.md는 T1과 관련된 원문을 모아 둔 파일입니다. T2를 고르면 T2_read.md를 여시면 되고, 다른 토픽도 같은 방식입니다. Markdown 파일은 Ctrl+Shift+V를 눌러 미리보기로 보시면 읽기 편합니다. Mac에서는 Cmd+Shift+V를 사용하시면 됩니다. document_topics.csv에는 모든 문서의 비중과 원문 위치가 들어 있습니다. 지금은 파일을 전부 열 필요 없이 topics.md부터 보겠습니다. 여러분이 관심 있는 토픽을 골랐을 때 그 토픽의 원문 파일로 이동하시면 됩니다.

## 13. 단어 목록에서 하나를 골라 원문으로 이동

지금 topics.md를 보면서 우리 조의 연구 주제와 관련 있어 보이는 토픽을 하나 골라 주세요. 번호가 앞에 있다고 더 중요한 토픽은 아닙니다. 우선 단어 목록만 보고 어떤 이야기일 것 같은지 조원에게 말해 보세요. 짧은 이름을 붙여도 좋고, 아직 잘 모르겠다고 말해도 괜찮습니다. 다음에는 선택한 번호의 원문 파일을 열어 주세요. T1을 골랐다면 T1_read.md입니다. 그 파일에서 비중이 높은 글부터 읽어보겠습니다. 여러분이 붙인 이름으로 그 글의 내용을 설명할 수 있는지 보시면 됩니다. 원문에서 다른 이야기가 나온다면 단어 목록으로 돌아가기보다 그 글을 끝까지 읽어 주세요.

## 14. 원문을 읽고 이름을 바꿔도 됩니다

원문 파일에는 해당 토픽의 비중이 높은 글이 최대 다섯 개 들어 있습니다. 먼저 글쓴이가 무엇을 좋다고 하거나 불편하다고 하는지 읽어 주세요. 다른 글에서도 같은 대상을 이야기하는지 이어서 보시면 됩니다. 같은 단어가 나온다는 이유만으로 입장까지 같다고 생각하지는 마세요. 어떤 사람은 같은 제도를 지지하고 다른 사람은 비판할 수 있습니다. 그럴 때는 찬성이나 반대만 담은 이름보다 두 글이 공통으로 다루는 쟁점을 이름에 담는 편이 낫겠습니다. 처음 붙인 이름이 맞지 않으면 조원들과 바꿔 보세요. 제가 원문을 함께 보면서 이름이 너무 넓거나 좁지는 않은지 설명해드리겠습니다. 화면에 있는 CSV 행 번호로 원본에서도 같은 글을 찾을 수 있습니다.

## 15. 원문을 읽어도 토픽이 잘 설명되지 않을 때

어떤 조는 단어 목록이 꽤 또렷하고, 어떤 조는 비슷한 말만 반복될 수 있습니다. 그럴 때 제가 먼저 확인해드릴 부분은 입력한 본문 열과 전처리 결과입니다. 본문 대신 제목이나 작성자 정보를 읽었다면 설정부터 수정해야 합니다. 광고 문구나 작품명이 모든 글에 반복되면 공통 단어가 주제를 가릴 수도 있습니다. tokens_preview.csv를 열어서 코드가 실제로 어떤 단어를 사용했는지 봐 주세요. 필요하면 stopwords.txt에 해당 단어를 한 줄씩 추가하고 run을 다시 실행할 수 있습니다. 원문을 읽어도 여러 이야기가 너무 넓게 섞여 있다면 토픽 수를 바꿔 비교해 볼 수 있습니다. 다만 모양이 예뻐졌다는 이유만으로 좋은 결과라고 판단하기보다, 바뀐 결과가 원문을 더 잘 설명하는지 확인해 주세요.

## 16. 날짜가 있는 조는 월별 변화도 볼 수 있습니다

여기까지가 모든 조가 진행할 수 있는 원문 해석 부분입니다. 이제 여러분의 자료에 작성일이 들어 있는지 확인해 주세요. 작성일이 없으면 지금 읽고 있던 토픽의 다른 원문을 계속 보시면 됩니다. 날짜를 임의로 만들어 넣을 필요는 없습니다. 작성일이 있더라도 자료가 한 달 안에만 모여 있으면 이번 코드로 월별 변화를 비교할 수 없습니다. 서로 다른 달의 글이 있는 조는 date_column에 작성일 열 이름을 넣고 run을 다시 실행해 주세요. 이때 코드가 전체 기간의 문서를 한꺼번에 학습합니다. 월마다 토픽을 따로 만들면 같은 번호라도 다른 이야기를 가리킬 수 있기 때문에 공통 모델을 사용하는 것입니다. 준비가 된 조만 다음 명령으로 이어가겠습니다.

## 17. 월별 비중 그래프 열기

날짜를 설정해서 run까지 실행한 조는 화면의 time 명령을 입력해 주세요. 코드가 같은 모델의 토픽 비중을 월별로 모아서 평균을 계산합니다. 결과 폴더에 time_comparison.png가 생기면 그 파일을 열어 주세요. 그래프에서 각 선은 T1, T2와 같은 토픽 하나를 뜻합니다. 아래쪽 월 표기에는 그 달에 분석한 문서 수가 함께 나옵니다. 여러분이 앞에서 읽은 토픽의 선을 찾아서 어떤 달에 비중이 달라지는지 보시면 됩니다. 날짜가 없거나 한 달뿐이라는 메시지가 나오면 원문 해석으로 돌아가시면 됩니다. 그래프가 만들어졌다면 선이 올라간 이유를 바로 붙이기 전에 수치의 뜻부터 같이 보겠습니다.

## 18. 문서 수와 토픽 비중은 따로 읽습니다

수치 표에는 서로 다른 값이 나옵니다. n_documents는 그 달에 실제 분석한 전체 문서 수입니다. dominant_count는 해당 토픽이 가장 큰 비중을 차지한 문서의 개수입니다. mean_proportion은 그 달의 모든 문서에서 해당 토픽의 비중을 평균한 값이고, 그래프는 이 값을 백분율로 보여줍니다. 관련 글의 수가 늘어도 전체 글이 더 크게 늘었다면 평균 비중은 줄 수 있습니다. 그래서 제가 여러분께 먼저 보시라고 말씀드리는 것은 월별 전체 문서 수입니다. 댓글을 더 많이 수집한 달과 적게 수집한 달을 같은 조건이라고 생각하면 해석이 달라질 수 있습니다. 다음에는 비중이 달라진 달의 원문을 찾아보겠습니다.

## 19. 변화가 보이는 달의 글을 다시 읽어봅니다

관심 있는 토픽의 비중이 달라진 달이 있다면 document_topics.csv를 열어 주세요. 엑셀에서 period 열을 해당 월로 필터하고, 선택한 토픽의 비중을 큰 순서로 정렬하면 관련 글을 찾기 쉽습니다. 비교하려는 다른 달에서도 같은 방식으로 글을 읽어 주세요. 두 달의 글이 같은 대상을 이야기하는지, 불만이나 기대의 내용이 달라졌는지 보시면 됩니다. 원문에서 변화가 보이더라도 바로 전체 팬이나 관객의 생각이 바뀌었다고 말하기는 어렵습니다. 여러분이 수집한 게시물이나 영상이 달라졌을 수도 있기 때문입니다. 조원들과 수집 범위가 같았는지도 함께 확인해 주세요. 저는 여러분이 발견한 차이를 원문으로 보여주시면, 어디까지 설명할 수 있을지 같이 살펴보겠습니다.

## 20. 이제 각 조의 파일로 진행해 주세요

이제 각 조에서 직접 진행해 주세요. CSV를 지정한 위치에 넣고, text_column을 맞춘 뒤 run 명령을 실행하시면 됩니다. 분석이 끝나면 topics.md에서 관심 있는 토픽을 골라 주세요. 그다음 같은 번호의 원문 파일을 열고 조원들과 함께 읽으시면 됩니다. 이름이 잘 붙지 않는 토픽이나 서로 다른 입장이 섞인 글이 있으면 그 화면을 그대로 열어 두세요. 제가 각 조의 결과를 보면서 어떤 부분에서 해석이 막히는지 함께 이야기하겠습니다. 작성일이 여러 달에 걸친 조는 time 명령으로 그래프까지 보셔도 됩니다. 보고서나 해석 양식을 별도로 작성해서 제출하실 필요는 없습니다. 오늘은 여러분이 가진 자료에 코드를 적용하고, 실제 원문과 결과가 어떻게 연결되는지 함께 확인하겠습니다.
