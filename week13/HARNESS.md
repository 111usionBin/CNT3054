# 두 모델에 같은 판단을 요청하는 법

**평가문서**는 사람이 합의한 판단 기준이다. **평가 하네스**는 같은 입력을 만들고, 모델을 호출하고, 출력이 규칙을 지키는지 검사하고, 사람의 평가와 대조하는 코드다. 이 프로젝트에서는 평가문서의 실행 가능한 원본이 `codebook.json`, 실행 절차가 `lab.py`이다.

## 공통 평가문서를 직접 써 보기

| 결정할 것 | 이 프로젝트의 기준 | 실습할 때 해 볼 변경 |
|---|---|---|
| 단위·문맥 | 시작 시각순 1발화를 판정한다. 대상 앞 280자, 직전 발화 끝 110자, 직후 발화 앞 110자를 양쪽 모델에 동일하게 준다. 초과 부분은 생략한다. | 다음 발화를 가리면 대명사나 반전 판정이 어떻게 달라질지 예상한다. 이 기본 실습은 전사 완료 후 분석한다. |
| 후보 화자 | 영상별 역할 소개와 해당 발화의 1인칭 행동·호칭·어휘로 판단한다. | 후보 둘이 같은 역할이면 무엇으로 구분할 수 있는지 적는다. |
| 감정 | 기쁨(안도·감사 포함), 불안, 아쉬움, 복합, 중립, 판단유보. 대상 화자가 표현한 감정을 고른다. | “아쉽지만 기뻐요”를 복합으로 잡을 근거를 다른 조에 설명한다. |
| 서사 | 기=상황 소개, 승=사건 전개·심화, 전=방향 전환, 결=결과·회고. 해당없음=운영 안내 등, 판단유보=근거 부족. | 광고가 시작된 구간, 결말 없는 생방송에서 무리한 라벨을 피한다. |
| 증거·판정 | 같은 ID, 단서와 규칙으로 팀원이 독립 판정한다. 두 기준이 충돌하면 합의 근거를 한 줄 남긴다. | 표시할 수 있는 원문과 사건 경계를 함께 적는다. |
| 출력·비교 | 허용 라벨 3개 축을 확인하고, GPT가 낸 근거가 대상 발화에 있는지도 검사한다. | 모델 간 일치와 사람 합의표 대비 정확도를 서로 다른 열에서 읽는다. |

**‘중립’, ‘해당없음’, ‘판단유보’ 구분 연습.** “분실물 창구는 오른쪽입니다”는 사실 안내이므로 감정 중립, 공연 사건과 무관하므로 서사 해당없음이다. “네.”는 지시 대상이나 화자를 파악할 단서가 부족해 유보할 수 있다. 팀 프로젝트에서 ‘분노’를 새 감정으로 넣으려면 기존 기준에서 처리할 수 없는 발화부터 찾아본다.

### 한 발화가 두 API로 가는 과정

1. `lab.py / context`가 **target, previous, following, profiles, rubric**을 만든다. 기존 음성 화자 ID, 화자 이름, 사람 평가표는 두 모델의 요청에서 제외한다. 후보 목록에 모든 화자 ID가 들어가지만 대상 발화의 기존 번호는 가려진다. 시각과 ID는 저장할 때 원본에서 결합한다.
2. BERT 어댑터는 역할 소개와 `hypotheses`의 짧은 후보 문장을 NLI 가설로 읽는다. 각 가설의 ‘함의 대 모순’ 상대 점수를 대상만 읽은 점수 80%와 앞뒤 문맥을 포함한 점수 20%로 합친다. 한 라벨에 여러 가설이 있으면 최댓값을 쓴다. 최고 점수 0.60 미만, 1·2위 차이 0.08 미만, 대상이 두 글자 이하면 유보한다. 이는 수업용 결정 규칙이다. 상대 점수는 정답일 확률로 해석할 수 없다. 중립 점수는 이 상대값에서 제외되고 짧은 감탄사는 일괄 유보될 수 있다.
3. GPT 어댑터는 같은 평가문서와 대화를 지시문 및 데이터로 구분해 보낸다. 엄격한 JSON Schema가 후보 목록을 제한하고, 프로그램이 원문 인용을 다시 검증한다. 모델의 감정·서사 해석이 맞는지는 별도 평가한다. BERT의 후보 점수와 생성 모델의 인용은 서로 다른 종류의 근거다.
4. 실행 결과는 기존 번호, 예측 번호, 발화 ID, 시각과 함께 저장된다. 유보를 포함한 정확도의 분모는 사람이 값을 채운 발화 수다. 빈칸을 유보로 바꾸지 않는다. 상황에 따라 친절한 진행 멘트가 다른 사람의 불안을 묘사할 수 있으니 ‘누구의 감정인지’도 확인한다.

### 요청과 응답을 한 건 손으로 따라가기

대상은 “객석이 노래하네요. 제가 객석 마이크를 올려서 그 소리를 무대에 보낼게요.”이다. 역할 소개에서 ‘음향 감독’을 후보로 찾고 ‘객석 마이크를 올려서’에 밑줄을 긋는다. 아래는 **형식 설명용 응답**이다.

```json
{
  "speaker": "SPEAKER_01",
  "emotion": "중립",
  "stage": "전",
  "evidence": "제가 객석 마이크를 올려서"
}
```

‘승’이라고 읽은 학생은 사건의 전환이 직전 진행자의 제안에서 이미 일어났는지 확인한다. 원문 인용이 같더라도 단위와 경계의 정의에 따라 결론이 달라질 수 있다. 짧은 창에서 판단한 결과는 영상 전체의 완성된 서사를 보장하지 않는다.

### 기준을 한 가지 바꾸는 실험

1. 모델 답을 보기 전에 조별로 개발용 클립과 마지막 확인용 클립을 나눈다. 같은 영상에서 나누면 인접 발화가 겹치지 않게 장면 단위로 분리한다.
2. 개발용에서 ‘복합’ 판정이 갈린 발화를 찾는다. `codebook.json`의 `emotion.복합` 정의와 `hypotheses.emotion.복합`의 짧은 예문을 **같은 변경 취지**로 고치고 version을 올린다. 정의만 바꾸면 BERT는 기존 가설로 계속 채점하므로 둘을 같이 본다. 평가할 발화 원문을 예문으로 복사하지 않는다.
3. 같은 입력에 새 출력 폴더로 다시 실행한다. 같은 발화 수·같은 후보 소개·같은 사람표를 유지한다. 모델이 유보를 덜 했는지, 실제로 맞힌 건수도 늘었는지 분리해 본다.
4. 합의가 끝난 뒤 따로 둔 클립에 한 번 적용한다. 발표 때는 **영상/발화 수, 모델별 유보 건수, 사람과 맞힌 건수/분모, 갈린 장면 ID와 시각**을 함께 제시한다.
