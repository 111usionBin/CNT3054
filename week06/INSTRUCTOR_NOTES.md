# Week 6 실습 운영 메모

## 목표와 운영 (약 75–90분, 수업 시간에 맞게 조정)

- 0–10분: 지난 주의 사전 기반 점수와 이번 주의 라벨 기반 학습 구분
- 10–20분: 데이터 카드와 라벨 기준, 그룹 분리, 학습/검증/테스트 역할
- 20–35분: Pipeline 실행, TF-IDF 행렬과 학습 전용 fit 확인
- 35–50분: 기준선/두 후보의 검증 비교와 혼동행렬 계산
- 50–65분: 오류 원문과 계수 읽기, 개선 가설 작성
- 65–75분: 비교 종료 선언 후 최종 테스트, 짧은 보고 문장 작성
- 선택 확장: 실제 CSV의 라벨링 계획과 작품/작성자/시간 기준 분리 설계

실습 실패 학생은 `examples/`의 검증 결과 CSV로 지표와 오류 해석을 먼저 진행할 수 있다.
설치 경로를 설명할 때 기존 OS 설치 스크립트와 Python 의존성 파일을 구분한다.
명령줄의 python 대신 README에 있는 OS별 가상환경 실행 파일을 사용하게 한다.

## 실측 실행 결과

자료 120개, 그룹 60개, seed=42. 학습 72개(라벨별 36), 검증 24개(라벨별 12), 테스트 24개(라벨별 12).
모든 TF-IDF/분류기 학습은 학습 세트에만 수행했다. 모델 선택 후 검증을 합쳐 재학습하지 않았다.

- 검증 기준선: Accuracy 0.5, 긍정 Precision/Recall/F1 0, Macro-F1 0.3333
- 검증 unigram: 모든 표시 지표 0.8333, 혼동행렬 [[10,2],[2,10]]
- 검증 unigram+bigram: 모든 표시 지표 0.8333, 동점 규칙으로 unigram 선택
- 최종 테스트 unigram: Accuracy 0.8333, 긍정 Precision 0.7857, Recall 0.9167, F1 0.8462, Macro-F1 0.8322
- 최종 테스트 혼동행렬: [[9,3],[1,11]], 행 실제/열 예측, 순서 0/1

Bigram이 성능을 개선했다고 서술하면 이 실행 결과와 모순이다. “변경했지만 이 검증 표본에서는 지표가 같았다”가 정확하다.
자료/모델/seed를 최종 테스트 수치에 맞춰 조정하지 않는다. 예제 점수는 실행 검증과 해석 연습용이다.

## 질문별 해설

1. **슬픈 결말인데 훌륭했다:** 작품 내용의 정서와 감상자의 평가 방향은 다른 구성개념이다. 교육용 라벨은 전체적인 호평이므로 1이다.
2. **왜 학습 자료에서만 TF-IDF를 fit하는가:** 어휘 선택과 IDF도 자료에서 배운다. 전체 자료에서 fit하면 평가 자료의 분포 정보가 들어간다.
3. **왜 같은 그룹을 묶는가:** 원래 예제의 긍정/부정 대응문장이 양쪽에 들어가면 새 문장에 대한 평가가 지나치게 쉬워질 수 있다. 그룹 분리도 모든 유사성과 현실 간 차이를 제거하지는 않는다.
4. **기준선의 Accuracy 0.5가 괜찮은가:** 균형 자료에서 한 라벨만 내도 얻는 값이다. 이 숫자만으로 유용성을 주장할 수 없다. 불균형이면 정확도가 더 높아질 수도 있다.
5. **긍정 F1과 Macro-F1:** 전자는 긍정만, 후자는 두 라벨을 같은 비중으로 평균한다. 표의 열 이름을 축약하여 같은 지표처럼 읽지 않는다.
6. **Bigram의 동점:** 단어 조합은 일부 표현을 담지만 희소성이 늘고 이 표본은 작다. 동점의 원인을 확정할 수 없으며 별도 검증이 필요하다.
7. **p_positive≈0.5:** 중립이라는 뜻이 아니다. 이 모델은 중립 범주를 학습하지 않았고 확률 보정도 하지 않았다.
8. **계수:** 양수면 긍정 log-odds 방향, 음수면 부정 방향이다. 단어의 본질적 감성값·인과효과·관객 모집단의 태도는 아니다.
9. **테스트를 본 뒤 수정:** 이후 평가에는 새 독립 테스트 자료가 필요하다. 같은 데이터의 seed만 바꿔 좋은 점수를 찾는 것은 해결책이 아니다.

## 토론에 좋은 실제 검증 오류

- SYN012: “주인공의 행동이 이해되지 않아 답답했다.” 정답 0, 예측 1, p=0.5022, 일치 특징 1개
- SYN025: “인물들의 대화가 자연스럽고 이야기가 재미있다.” 정답 1, 예측 0, p=0.4872, 일치 특징 2개
- SYN057: “음악과 이야기가 자연스럽게 이어져 만족했다.” 정답 1, 예측 0, p=0.4847, 일치 특징 2개
- SYN092: “동선이 복잡해서 둘러보는 내내 답답했다.” 정답 0, 예측 1, p=0.5046, 일치 특징 0개

마지막 예제는 입력 벡터가 모두 0이라 절편만으로 결정한다. 낮은 어휘 커버리지와 한국어 활용형 차이를 살필 근거가 된다.
이 네 오류를 모두 반어나 부정어 문제라고 단정하면 안 된다. 실제 특징과 원문을 확인한다.

계수 예: 좋았다 +0.8229, 훌륭했다 +0.4612, 아쉬웠다 −0.6489, 어려웠다 −0.5679, 이야기가 −0.3768.
“이야기가”의 음수 계수로 모든 이야기 언급을 부정이라 해석해서는 안 된다.

## 학생 제출 기준 (10점 예시)

- 2점: 라벨의 측정 대상과 합성 데이터 한계 설명
- 2점: 그룹/학습/검증/테스트 분리와 누출 방지 설명
- 2점: 혼동행렬에서 Precision/Recall/F1 계산 및 기준선 비교
- 2점: 원문 오류 2개와 검증 가능한 개선 가설
- 2점: 테스트 사용 시점과 일반화 한계가 포함된 결과 보고

높은 점수 자체를 평가 기준으로 삼지 않는다. 코드를 전부 외우는 것보다 절차와 문화적 해석을 설명하도록 한다.
